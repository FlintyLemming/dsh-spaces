# dsh-spaces 加固与端到端实施计划（计划 07 / 共 07）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成平台加固与交付：Docker 主机版租户出口防火墙（fail-closed 启动校验）、镜像构建管线安全回归测试、平台部署产物（Dockerfile + compose）、E2E 冒烟（mock IdP + 假 dsh 镜像跑通主链路）。

**Architecture:** 防火墙移植 portal 的 nftables 思路但从 podman-machine 适配到宿主机 Docker：`firewall/apply.sh` 在宿主机以 root 执行，对 `dsh-tenants` 网桥子网在 `forward` 链 drop RFC1918/loopback/link-local/云元数据；平台容器以 `network_mode: host` 运行（实例端口发布在宿主机 loopback，网关经共享网络命名空间访问），启动时用探针容器验证防火墙已生效（探针连通则拒绝启动）。E2E 用三件套：mock OIDC IdP（零依赖 node:http + 手搓 RS256）、假 dsh 镜像（任意路径返回 200）、真实平台容器，驱动脚本走完整「OIDC 登录 → 个人空间 → 启动实例 → 路径反代」链路。

**Tech Stack:** nftables, dockerode, Docker multi-stage build, docker-compose, node:crypto（RS256 手写签名）, Vitest（E2E 以 `E2E=1` 门控）。

**Spec:** `docs/superpowers/specs/2026-09-04-dsh-spaces-design.md`（§2 部署拓扑、§7 安全设计、§9 fail-closed、§10 测试策略、§11 移植清单）

**前置计划：** 01（config/store/server/docker.js）、02（认证与管理员引导）、03（编排、`ensureTenantNetwork()`、`scripts/build-image.sh`、`scripts/set-image-digest.js`）、04（网关）、06（管理 API：`PUT /api/admin/settings`、`PUT /api/admin/image/digest`）。本计划严格复用其接口与命名。

## Global Constraints

- 沿用计划 01 全部 Global Constraints（ESM JS、错误格式、提交风格、配置键名等）。
- `firewall/apply.sh` 在**宿主机**以 root/sudo 执行，不在平台容器内执行（平台容器无 NET_ADMIN，也不该有）。
- 防火墙未生效时平台**拒绝启动**（fail-closed，spec §9）；唯一豁免是开发环境显式 `FIREWALL_REQUIRED=false`。
- 平台容器 v1 以 root 运行并挂载 `/var/run/docker.sock`——socket 本身即宿主 root 等价，容器内降权无收益；此权衡必须写进 Dockerfile 注释与 README。
- E2E 测试默认跳过，仅 `E2E=1` 且本机有 Docker 时运行；`npm test` 不得依赖 Docker 守护进程。
- 探针镜像固定 `alpine:3`（需可 pull；部署文档写明前置 `docker pull alpine:3`）。
- shell 脚本一律 `set -euo pipefail`。

### Task 2: 租户出口防火墙（Docker 宿主机适配）

**Files:**
- Create: `firewall/tenant-egress.nft`
- Create: `firewall/apply.sh`

**Interfaces:**
- Consumes: `config.instanceNetwork`（默认 `dsh-tenants`，计划 03 的 `ensureTenantNetwork()` 创建该网桥）。
- Produces: 宿主机 nftables 表 `inet dsh-tenant-egress`；`firewall/apply.sh` 幂等应用。Task 3 的探针验证本任务产出的规则确实生效。

设计决策（相对 portal 的适配点）：
- portal 的规则作用于 podman machine 的 rootless pasta 网络；dsh-spaces 用宿主机 Docker 网桥，规则挂在 `forward` 链、按 `dsh-tenants` 子网匹配源地址。
- **子网在 apply 时动态取**：`docker network inspect` 读 `dsh-tenants` 的 IPAM 子网，sed 替换模板占位符后管道给 `nft -f -`（nft 规则文件不读环境变量）。
- **云元数据 169.254.169.254 单独一条 drop**（带独立注释），不与 169.254/16 合并——防止将来有人"清理 link-local 规则"时误删。
- 172.16/12 会覆盖租户子网自身（Docker 网桥默认从该段分配），所以**先放行子网内部流量**再 drop（v1 允许同空间实例互通；收紧留给后续，注释说明）。

- [ ] **Step 1: 写 firewall/tenant-egress.nft**

```
# dsh-spaces 租户出口防火墙（宿主机 Docker 版，移植改造自 portal firewall/）。
# apply.sh 会将 @TENANT_SUBNET@ 替换为 dsh-tenants 网桥的实际子网后经 nft -f 加载。
# 语义：实例容器可出公网（模型 API 等），禁止触达内网/loopback/link-local/云元数据。
table inet dsh-tenant-egress {
    chain forward {
        type filter hook forward priority 0; policy accept;

        # v1 允许租户子网内部互通（同空间成员实例间无直接通信需求，放行无害；
        # 如需收紧为仅允许网关，改此行即可）。
        ip saddr @TENANT_SUBNET@ ip daddr @TENANT_SUBNET@ accept comment "intra-tenant subnet (v1 allow)"

        # 云实例元数据端点单独成条：永远不要因为"清理 link-local"而移除它。
        ip saddr @TENANT_SUBNET@ ip daddr 169.254.169.254 drop comment "cloud instance metadata endpoint"

        ip saddr @TENANT_SUBNET@ ip daddr 127.0.0.0/8 drop comment "loopback"
        ip saddr @TENANT_SUBNET@ ip daddr 169.254.0.0/16 drop comment "link-local"
        ip saddr @TENANT_SUBNET@ ip daddr 10.0.0.0/8 drop comment "private 10/8"
        ip saddr @TENANT_SUBNET@ ip daddr 172.16.0.0/12 drop comment "private 172.16/12"
        ip saddr @TENANT_SUBNET@ ip daddr 192.168.0.0/16 drop comment "private 192.168/16"
    }
}
```

- [ ] **Step 2: 写 firewall/apply.sh**

```bash
#!/bin/bash
# Apply the dsh-spaces tenant egress firewall on the Docker HOST (idempotent).
# 在宿主机以 root/sudo 执行；平台首次启动（创建 dsh-tenants 网络）之后运行。
set -euo pipefail
cd "$(dirname "$0")"

NETWORK="${TENANT_NETWORK:-dsh-tenants}"
SUBNET="$(docker network inspect -f '{{range .IPAM.Config}}{{.Subnet}}{{end}}' "$NETWORK" 2>/dev/null || true)"
if [ -z "$SUBNET" ]; then
  echo "error: docker network '$NETWORK' not found;" >&2
  echo "  start the platform once (it creates the network), or: docker network create '$NETWORK'" >&2
  exit 1
fi

echo "firewall: tenant network '$NETWORK' subnet $SUBNET"

# 幂等：先删旧表再整体加载。
nft delete table inet dsh-tenant-egress 2>/dev/null || true
sed "s|@TENANT_SUBNET@|$SUBNET|g" tenant-egress.nft | nft -f -

echo 'firewall: applied:'
nft list table inet dsh-tenant-egress
```

```javascript
// src/orchestrator/firewall-check.js

// 探针目标取云元数据端点：它是规则表里最不可少的一条，且公网不可路由——
// 正常网络环境下它必然不可达，可达只能说明 forward 链没拦住租户子网。
const PROBE_TARGET = '169.254.169.254'
// 固定 alpine:3（busybox wget -T 超时）。dsh 镜像里没有 wget，不能拿 image_digest 当探针。
const PROBE_IMAGE = 'alpine:3'

export async function verifyTenantFirewall(docker, config) {
  if (!config.firewallRequired) {
    console.warn('[firewall] FIREWALL_REQUIRED=false — 未验证租户出口防火墙；严禁用于生产')
    return false
  }
  let container
  try {
    container = await docker.createContainer({
      Image: PROBE_IMAGE,
      Cmd: ['wget', '-T', '3', '-q', '-O', '/dev/null', `http://${PROBE_TARGET}/`],
      HostConfig: { NetworkMode: config.instanceNetwork, AutoRemove: true },
    })
  } catch (err) {
    throw new Error(`firewall probe container could not be created (is ${PROBE_IMAGE} pulled?): ${err.message}`)
  }
  try {
    await container.start()
    const { StatusCode } = await container.wait()
    if (StatusCode === 0) {
      throw new Error(
        `tenant egress firewall is NOT applied: a probe from network "${config.instanceNetwork}" ` +
        `reached ${PROBE_TARGET}. Run sudo firewall/apply.sh on the docker host (fail-closed, spec §9)`,
      )
    }
    return true
  } finally {
    // AutoRemove 生效时 remove 会 404，忽略。
    try { await container.remove({ force: true }) } catch { /* already gone */ }
  }
}
```

两个关键决策（写进 Dockerfile/compose 注释与 README）：
1. **`network_mode: host`**：实例容器把端口发布到宿主机 `127.0.0.1:<port>`（spec §7：端口只绑 loopback），平台容器要反代就必须与宿主机共享网络命名空间。这也决定了 compose 里不能写 `ports:`，监听端口由 `PORT` 环境变量控制，TLS 终结由前置反代（如 Caddy/nginx）负责。
2. **平台容器 root**：挂载 `/var/run/docker.sock` 即宿主 root 等价，容器内降权无实际隔离收益（spec §2 部署拓扑的必然结果）；注释明示。

`.dockerignore` 冲突处理：计划 03 的根 `.dockerignore` 是**镜像构建管线**的白名单（deny-by-default + `!dsh/`、`!image/...`），它同时会被根 `docker build` 使用。解决：平台构建上下文与镜像构建上下文分离——`scripts/build-image.sh` 用 `git archive` 生成独立 CONTEXT 目录并把白名单 `.dockerignore` 复制进去（portal 已是此模式），因此根 `.dockerignore` 可以按平台构建需要自行维护：

// test/e2e/mock-idp/server.mjs — E2E 专用最小 OIDC IdP。非生产代码。
import { createServer } from 'node:http'
import { readFileSync } from 'node:fs'
import { createPrivateKey, sign as cryptoSign } from 'node:crypto'

const ISSUER = process.env.ISSUER ?? 'http://localhost:19999'
const PORT = Number(process.env.PORT ?? 9999)
const CLIENT_ID = 'dsh-spaces-e2e'
const CODE = 'e2e-auth-code'
const privateKey = createPrivateKey(readFileSync(new URL('./key.pem', import.meta.url)))
const jwks = JSON.parse(readFileSync(new URL('./jwks.json', import.meta.url)))

let lastNonce = null // authorize 时记录，token 时放回 ID token

const b64url = (s) => Buffer.from(s).toString('base64url')
function idToken() {
  const now = Math.floor(Date.now() / 1000)
  const header = b64url(JSON.stringify({ alg: 'RS256', kid: jwks.keys[0].kid, typ: 'JWT' }))
  const payload = b64url(JSON.stringify({
    iss: ISSUER, sub: 'e2e-sub-1', aud: CLIENT_ID,
    email: 'e2e@example.com', email_verified: true, name: 'E2E User',
    iat: now, exp: now + 600,
    ...(lastNonce ? { nonce: lastNonce } : {}),
  }))
  const sig = cryptoSign('sha256', Buffer.from(`${header}.${payload}`), privateKey).toString('base64url')
  return `${header}.${payload}.${sig}`
}

const server = createServer((req, res) => {
  const url = new URL(req.url, ISSUER)
  if (url.pathname === '/.well-known/openid-configuration') {
    res.end(JSON.stringify({
      issuer: ISSUER,
      authorization_endpoint: `${ISSUER}/authorize`,
      token_endpoint: `${ISSUER}/token`,
      jwks_uri: `${ISSUER}/jwks`,
      response_types_supported: ['code'],
      subject_types_supported: ['public'],
      id_token_signing_alg_values_supported: ['RS256'],
    }))
    return
  }
  if (url.pathname === '/jwks') {
    res.end(JSON.stringify(jwks))
    return
  }
  if (url.pathname === '/authorize') {
    // 免交互：直接按测试用户放行。校验 redirect_uri 同源，防夹具被误用成开放重定向器。
    const redirectUri = url.searchParams.get('redirect_uri') ?? ''
    if (!redirectUri.startsWith('http://localhost:18080/')) {
      res.writeHead(400).end('bad redirect_uri')
      return
    }
    lastNonce = url.searchParams.get('nonce')
    const target = new URL(redirectUri)
    target.searchParams.set('code', CODE)
    target.searchParams.set('state', url.searchParams.get('state') ?? '')
    res.writeHead(302, { location: target.toString() }).end()
    return
  }
  if (url.pathname === '/token' && req.method === 'POST') {
    let body = ''
    req.on('data', (c) => { body += c })
    req.on('end', () => {
      const params = new URLSearchParams(body)
      if (params.get('code') !== CODE) {
        res.writeHead(400, { 'content-type': 'application/json' })
          .end(JSON.stringify({ error: 'invalid_grant' }))
        return
      }
      res.writeHead(200, { 'content-type': 'application/json' }).end(JSON.stringify({
        access_token: 'e2e-access-token', token_type: 'Bearer', expires_in: 600,
        id_token: idToken(),
      }))
    })
    return
  }
  res.writeHead(404).end('not found')
})
server.listen(PORT, () => console.log(`mock-idp on ${PORT}, issuer ${ISSUER}`))
```

import { test } from 'vitest'
import assert from 'node:assert/strict'
import { randomBytes, createHash } from 'node:crypto'

const BASE = process.env.E2E_BASE ?? 'http://localhost:18080'

class Browser {
  cookies = new Map()
  cookieHeader() {
    return [...this.cookies].map(([k, v]) => `${k}=${v}`).join('; ')
  }
  absorb(res) {
    for (const sc of res.headers.getSetCookie?.() ?? []) {
      const [pair] = sc.split(';')
      const eq = pair.indexOf('=')
      this.cookies.set(pair.slice(0, eq).trim(), pair.slice(eq + 1).trim())
    }
  }
  async fetch(path, opts = {}) {
    const res = await fetch(`${BASE}${path}`, {
      redirect: 'manual',
      ...opts,
      headers: { cookie: this.cookieHeader(), ...(opts.headers ?? {}) },
    })
    this.absorb(res)
    return res
  }
}

test('oidc login → personal space → instance → proxied dsh ui', { timeout: 180_000 }, async (t) => {
  if (process.env.E2E !== '1') return t.skip('set E2E=1 and run test/e2e/run.sh first')

  const b = new Browser()
  // 1) OIDC 登录：平台生成 PKCE/state/nonce 并 302 到 mock IdP。
  const login = await b.fetch('/api/auth/login?return_to=/')
  assert.equal(login.status, 302)
  const authorizeUrl = login.headers.get('location')
  assert.ok(authorizeUrl.startsWith('http://localhost:19999/authorize'))

  // 2) mock IdP 直接放行，302 回平台 callback（驱动跟随两个 302）。
  const authz = await b.fetch(new URL(authorizeUrl).pathname + new URL(authorizeUrl).search
    .replace(/^/, (s) => s).replace('http://localhost:19999', ''))
  // 注意：authorize 在 IdP 上，不走平台 BASE——单独 fetch：
  // （上行仅为说明，实际请求见下方 idpRes）
  const idpRes = await fetch(authorizeUrl, { redirect: 'manual' })
  assert.equal(idpRes.status, 302)
  const callback = new URL(idpRes.headers.get('location'))
  const cb = await b.fetch(callback.pathname + callback.search)
  assert.equal(cb.status, 302)
  assert.ok(b.cookies.has('dsh_session'))

  // 3) 个人空间已惰性创建。
  const spaces = await (await b.fetch('/api/spaces')).json()
  assert.equal(spaces.spaces.length, 1)
  const space = spaces.spaces[0]
  assert.equal(space.kind, 'personal')
  const me = await (await b.fetch('/api/auth/me')).json()
  const handle = me.user.handle

  // 4) 启动实例并轮询到 running。
  const start = await b.fetch(`/api/spaces/${space.slug}/instance/start`, { method: 'POST' })
  assert.equal(start.status, 200)
  let inst
  for (let i = 0; i < 60; i += 1) {
    inst = await (await b.fetch(`/api/spaces/${space.slug}/instance`)).json()
    if (inst.status === 'running') break
    if (inst.status === 'error') assert.fail(`instance error: ${inst.error}`)

  assert.equal(inst.status, 'running')

  const page = await b.fetch(`/s/${space.slug}/${handle}/`)
  assert.equal(page.status, 200)
  assert.match(await page.text(), /fake dsh/)

  // 6) 停止实例。
  const stop = await b.fetch(`/api/spaces/${space.slug}/instance/stop`, { method: 'POST' })
  assert.equal(stop.status, 200)
})

## 部署（单机 Docker）

前置：Docker ≥ 24、nftables、Node 24（仅构建镜像时需要）。

1. 克隆上游 dsh 并 checkout 批准 commit（见 `scripts/build-image.sh` 顶部），构建实例镜像：
   `npm run build:image`（输出 `sha256:` digest）。
2. `cp .env.example .env` 并填写 `PLATFORM_ORIGIN`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`（≥16 位）。
3. `docker pull alpine:3`（防火墙探针镜像）。
4. `docker compose up -d`（首次启动创建 `dsh-tenants` 网络；此时启动校验会失败属预期）。
5. `sudo firewall/apply.sh`（应用租户出口防火墙）。
6. `docker compose restart platform`（fail-closed 校验通过，平台就绪）。
7. 浏览器打开平台，管理员密码登录 → 设置里配置 OIDC → 填实例镜像 digest → 建议关闭密码登录。

安全边界说明：平台容器挂载 /var/run/docker.sock（宿主 root 等价），v1 以 root 运行；
租户实例固定非 root UID、只读根 fs、no-new-privileges、限额、出口防火墙隔离。
```
